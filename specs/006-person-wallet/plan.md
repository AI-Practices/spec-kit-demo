# Implementation Plan: Person Wallet / Advance Ledger + Database Migration

**Branch**: `006-person-wallet` | **Date**: 2026-05-25 | **Spec**: spec.md

**Input**: Feature specification from `specs/006-person-wallet/spec.md` + user requirements: PostgreSQL setup, Prisma ORM, database schemas, data migration, Person Wallet module, dashboard summaries, filters, reports.

## Summary

Add PostgreSQL + Prisma ORM to the existing Next.js application, creating proper database schemas for all entities (persons, wallet_transactions, budgets, expenses, categories). Migrate existing localStorage data to PostgreSQL and replace localStorage logic with server action APIs that read/write through Prisma. Implement the full Person Wallet module with credit/debit tracking, monthly grid, automatic balance calculation, and person-wise summaries. Add dashboard summaries, filters, and reporting. Architect for future cloud sync, exports, and multi-user access.

## Technical Context

**Language/Version**: TypeScript 5 (strict mode)

**Primary Dependencies**: Prisma ORM (PostgreSQL adapter), PostgreSQL 16, existing Next.js 16 + React 19 + Zod 4 + Tailwind v4 stack

**Storage**: PostgreSQL database via Prisma ORM. Prisma Migrate for schema versioning. LocalStorage retained temporarily during migration phase, then deprecated.

**Testing**: No test framework configured yet. Manual testing and `npm run build` validation for this phase.

**Target Platform**: Web (Next.js 16 App Router on Node.js runtime)

**Project Type**: Full-stack web application (Next.js server actions + Prisma database)

**Performance Goals**: Summary views load in < 2s for 50 persons / 1000 transactions each. Monthly grid renders in < 1s. All database queries use appropriate indexes.

**Constraints**: Must co-exist with existing localStorage expense tracker during migration. Existing server action contracts must remain backward-compatible. No separate backend server — database accessed directly via Prisma within Next.js server runtime.

**Scale/Scope**: Single-user initially, schema designed for future multi-user via `user_id` foreign key on all tables.

| Stack consistency (§IV) | ⚠️ VIOLATION | Constitution states "No backend or database — frontend-only". PostgreSQL + Prisma adds a database. |
| Progressive enhancement (§V) | ✅ PASS | P1-P4 story ordering preserved |

**Violation Justification**: The constitution's "No backend or database" constraint predates the Person Wallet feature requirements. Adding PostgreSQL + Prisma is necessary because:
- The feature spec (FR-016) requires design for future cloud sync and multi-user — impossible with localStorage
- Next.js server actions with Prisma keep the architecture within the existing framework — no separate backend server
- This is an incremental evolution (add Prisma to existing Next.js project) rather than a fundamental architecture change
- Migration preserves all existing data and backward-compatible action contracts

**Decision**: VIOLATION JUSTIFIED — proceed. Constitution §Technology Stack needs amendment to reflect database support.
