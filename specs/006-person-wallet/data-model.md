## Entity: Person

Represents an individual for whom money is managed in the wallet/advance ledger.

| Field | Type | Required | Validation | Notes |
|-------|------|----------|------------|-------|
| `id` | `String` (cuid) | Auto | Generated by Prisma | Immutable unique identifier |
| `userId` | `String` | Yes | Must reference existing User | Foreign key for multi-user isolation |
| `name` | `String` | Yes | Non-empty, trimmed | Free text; duplicates allowed |
| `createdAt` | `DateTime` | Auto | | Set on creation |
| `updatedAt` | `DateTime` | Auto | | Updated on name edit |
| `deletedAt` | `DateTime?` | No | Null = active | Prepared for future soft-delete |

**Relationships**: Has many WalletTransactions (via `personId`)

**Indexes**: `(userId, deletedAt)`, `(userId, name)`

## Entity: WalletTransaction

Represents a single credit or debit entry for a person.

| Field | Type | Required | Validation | Notes |
|-------|------|----------|------------|-------|
| `id` | `String` (cuid) | Auto | Generated by Prisma | Immutable unique identifier |
| `userId` | `String` | Yes | Must reference existing User | Multi-user isolation |
| `personId` | `String` | Yes | Must reference existing Person | The person this transaction belongs to |
| `type` | `String` (enum) | Yes | `"credit"` or `"debit"` | Credit = money given, Debit = money deducted/spent |
| `amount` | `Int` | Yes | Positive integer (> 0), cents | Stored as integer cents |
| `date` | `DateTime` | Yes | Valid date; future allowed | Calendar date of the transaction |
| `notes` | `String` | For debits | Required for debits (non-empty), optional for credits | Reason/description |
| `createdAt` | `DateTime` | Auto | | Set on creation |

**Relationships**: Belongs to Person (via `personId`)

**Validation Rules**:
- `amount` must be > 0 (enforced by Zod)
- `type` must be exactly `"credit"` or `"debit"`
- `notes` must be non-empty when `type === "debit"`; optional when `type === "credit"`
- `date` can be past, present, or future (future dates represent planned credits)

**Indexes**: `(personId, date)`, `(userId, date)`, `(userId, personId)`

## Prisma Schema Structure

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        String   @id @default(cuid())
  email     String   @unique
  name      String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  persons             Person[]
  walletTransactions  WalletTransaction[]
  expenses            Expense[]
  categories          Category[]
  budgets             Budget[]
}

model Person {
  id        String   @id @default(cuid())
  userId    String
  name      String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  deletedAt DateTime?

  user       User                @relation(fields: [userId], references: [id])
  walletTransactions WalletTransaction[]

  @@index([userId, deletedAt])
  @@index([userId, name])
}

model WalletTransaction {
  id        String   @id @default(cuid())
  userId    String
  personId  String
  type      String   // "credit" | "debit"
  amount    Int
  date      DateTime
  notes     String?
  createdAt DateTime @default(now())

  user   User   @relation(fields: [userId], references: [id])
  person Person @relation(fields: [personId], references: [id])

  @@index([personId, date])
  @@index([userId, date])
  @@index([userId, personId])
}

model Expense {
  id          String   @id @default(cuid())
  userId      String
  categoryId  String
  amount      Int
  date        DateTime
  description String
  createdAt   DateTime @default(now())
  deletedAt   DateTime?

  user     User     @relation(fields: [userId], references: [id])
  category Category @relation(fields: [categoryId], references: [id])

  @@index([userId, date])
  @@index([userId, categoryId])
}

model Category {
  id        String   @id @default(cuid())
  userId    String
  name      String
  type      String   // "expense" | "income"
  icon      String?
  color     String?
  createdAt DateTime @default(now())
  deletedAt DateTime?

  user    User      @relation(fields: [userId], references: [id])
  expenses Expense[]
  budgets  Budget[]

  @@unique([userId, name])
  @@index([userId, deletedAt])
}

model Budget {
  id        String   @id @default(cuid())
  userId    String
  categoryId String
  amount    Int
  period    String   // "monthly" | "weekly" | "yearly"
  startDate DateTime
  endDate   DateTime?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  user     User     @relation(fields: [userId], references: [id])
  category Category @relation(fields: [categoryId], references: [id])

  @@index([userId, categoryId, period])
}
```

## Balance Calculation

A person's current balance is computed as:

```
balance = SUM(credits) - SUM(debits)
```

where:
- `SUM(credits)` = sum of `amount` for all `WalletTransaction` where `personId = X` and `type = "credit"`
- `SUM(debits)` = sum of `amount` for all `WalletTransaction` where `personId = X` and `type = "debit"`

This is computed via a Prisma aggregation query:
```ts
const result = await prisma.walletTransaction.aggregate({
  where: { personId, userId },
  _sum: { amount: true },
});
```

No separate `balance` field is stored — balance is always derived from transactions to prevent inconsistency.

## State Transitions

### Person
- **CREATE**: Person transitions from non-existent to active with name set
- **UPDATE**: Name can be edited after creation
- **DELETE**: Person transitions from active to deleted (hard delete — all transactions also removed). Future: soft-delete.

### WalletTransaction
- **CREATE**: Transaction recorded with type, amount, date, and notes
- **DELETE**: Transaction removed; balance recalculated on next query
- **UPDATE**: Not supported in v1 (corrections handled by delete + re-enter)

### Expense
- **CREATE**: Expense recorded (existing behavior, now via PostgreSQL)
- **DELETE**: Expense removed (existing behavior, now via PostgreSQL)
- **UPDATE**: Not supported in v1 (consistent with current app behavior)
