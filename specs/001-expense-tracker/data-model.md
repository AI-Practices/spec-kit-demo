# Data Model: Expense Tracker

## Entity: Expense

Represents a single financial transaction.

| Field | Type | Required | Validation | Notes |
|-------|------|----------|------------|-------|
| `id` | `string` (UUID v4) | Auto | Generated by `crypto.randomUUID()` | Immutable unique identifier |
| `amount` | `number` | Yes | Integer, positive (> 0), whole cents | Stored as cents; display as dollars |
| `date` | `string` | Yes | ISO 8601 date (YYYY-MM-DD), must be today or earlier | Restricted via `<input type="date" max={today}>` and Zod |
| `category` | `Category` | Yes | Must be one of the 8 predefined values | Dropdown selection |
| `description` | `string` | Yes | Non-empty, trimmed | Free text field |

## State Transitions

- **CREATE**: An expense transitions from non-existent to created with all fields populated and validated
- **DELETE**: An expense transitions from existing to deleted (permanent removal, no soft-delete)
- **UPDATE**: Not supported in v1 (no edit functionality)

## Validation Rules

All rules are enforced by Zod schemas shared between server actions and client components:

1. **id**: Auto-generated — no user input
2. **amount**: `z.number().int().positive("Amount must be a positive whole number (cents)")`
3. **date**: `z.string().regex(/^\d{4}-\d{2}-\d{2}$/).refine(val => val <= today, "Date cannot be in the future")`
4. **category**: `z.enum([...categoryLabels])`
5. **description**: `z.string().min(1, "Description is required").trim()`
